# Architecture: Portable Pipelines

Portable Pipelines is a portable implementation of IBM CMS Pipelines (z/VM). This document records the dispatcher model, the type map, and choices versus IBM.

## Design rules (Hartmann)

1. **Stages never call each other.** They call dispatcher services on `StageCtx`: `read`, `write`, `commit`, `delay_record`, `wait_until`, `stop_external_waits`, `short`, `callpipe`.
2. **Records**, not byte streams, are the unit of transfer (`pipe_core::Record`).
3. **At most one record in flight** per connection unless a stage explicitly buffers (`BUFFER`, `SORT`).
4. **Drain-biased scheduling:** consumers that can read are preferred over producers.
5. **Device drivers vs filters:** disk/command/console live in driver stages; filters only transform records.

## Type map

| CMS concept | Rust |
|---|---|
| Record | `pipe_core::Record` |
| Stream number | `pipe_core::StreamId` |
| Stage | coroutine running a `StageFn` / `FnOnce(&mut StageCtx)` |
| Dispatcher | `pipe_core::Dispatcher` via `PipelineBuilder::run` |
| PIPE specification | `pipe_parser::parse_pipeline` |
| Built-in program | factory in `pipe_stages::StageRegistry` |
| CALLPIPE | `StageCtx::callpipe` + connectors |
| REXX stage | `pipe_rexx` (`READTO` / `OUTPUT` / `CALLPIPE` / …) |
| Python stage | `pipe_python` (`.py` path; live `readto` / `peekto` / `output` / `short`) |

## Coroutine model

Each stage runs on a **stackful coroutine** (`corosensei`). When `read`/`write`/`commit` cannot complete, the stage **suspends**; the dispatcher resumes another ready stage. A thread-local holds the current `Yielder` so `StageCtx` stays easy to call.

## Multi-stream labels

```text
(ENDCHAR ?) literal a|literal b | L: locate /a/ | console ? L: | console
```

- First `L:` defines the stage and its primary streams.
- Later `L:` occurrences attach secondary/tertiary streams of that same stage instance.

## CALLPIPE / ADDPIPE

Nested specifications may start/end with IBM `*:` connectors (bare `*` still
accepted as a synonym):

- Leading `*:` — feed nested pipeline from the caller’s selected input.
- Trailing `*:` — drain nested output to the caller’s selected output.
- Also recognized: `*.input:`, `*.output:`.

v1 implements connector CALLPIPE in **buffering** mode (read all → run nested → write all), which is record-correct and sufficient for REXX filters. Streaming bridges can replace this later without changing the stage API. Buffering cannot hand an unconsumed nested record back to the caller, so TOLABEL / WHILELABEL leftover (p.559 / p.596) stays subset until Phase 4 Streaming CALLPIPE.

## REXX / Regina

`pipe-rexx` runs `.rexx` stages with this preference order:

1. **Regina** (user-installed) — dynamically load `regina.dll` / `libregina.so` / `libregina.dylib`, register ADDRESS `PIPELINE`, `RexxStart` the script file.
2. **Subset interpreter** — if Regina is not found or cannot load.

Discovery env vars: `PIPE_REGINA`, `REGINA`, `REGINA_HOME` (file or directory). Also searches PATH, the `pipe` executable directory, and common install prefixes (including Debian/Ubuntu multiarch dirs such as `/usr/lib/x86_64-linux-gnu`, where `libregina.so.3` is packaged).

Development install of Regina (library + `regina` / `rexx` binary):

- Linux (Debian/Ubuntu): `sudo apt-get update && sudo apt-get install -y regina-rexx libregina3-dev`
- macOS (Homebrew): `brew install regina-rexx`
- Windows: Regina installer, or the zip from `scripts/package-windows.ps1` (places `regina.dll` next to `pipe.exe` so executable-directory search succeeds). See [packaging.md](packaging.md).

`PIPE_REQUIRE_REGINA=1` makes tests fail if Regina is not discovered/loaded, so a missing install cannot silently use the subset interpreter. Cloud agents should export it before `cargo test`. It is **not** required for contributors without Regina; leave it unset so the suite still passes on the subset path. Cursor `environment.json` has no env-var field; the export is documented in `.cursor/rules/regina-rexx.mdc`. Cloud agent VMs install the Ubuntu packages via `.cursor/environment.json` `install`.

Pipeline subcommands use **IBM names only** (ADDRESS `PIPELINE` / subset statements):

| Subcommand | Meaning |
|---|---|
| `READTO var` | Read one record; RC=12 at EOF |
| `OUTPUT` | Write a record (command string after `OUTPUT` and one blank; blanks kept) |
| `CALLPIPE` | Nested pipeline |
| `ADDPIPE` | Attach nested network (v1 ≈ CALLPIPE) |
| `SHORT` | Sever selected streams |
| `SELECT INPUT/OUTPUT n` | Choose stream |
| `COMMIT n` | Commit level (Regina path) |
| `PEEKTO` | Not yet |

## Python stages

Non-IBM. Write a `.py` program that reads records from its input and writes records to its output, and name the file in the pipeline the same way you name a REXX stage. It is not a registry entry. The CLI installs `pipe_python::install_hook()`. Each stage is one system interpreter process (Python 3.10 or later), and REXX and Python stages can sit side by side in one pipeline. Interpreter discovery: `PIPE_PYTHON`, then `py -3` on Windows, then `python3`, then `python`. Protocol frames use duplicated stdin/stdout handles; `print()` is rebound to stderr. v1 is single-stream: a label that would connect a secondary stream fails with CMS stage context. See [`design/python-stages.md`](design/python-stages.md).

`pipe` makes the `pipelines` helper module available to each stage for you, so you don't set `PYTHONPATH` yourself. The host prepends the parent of `pipelines` to the child's `PYTHONPATH`, keeping any existing value and using the platform path separator. It looks in these places in order: `PIPE_PYTHONPATH` if set, then a `pipelines` folder next to the executable, then `env!("CARGO_MANIFEST_DIR")/python` when that tree is still on disk. If none is found, the stage fails and lists where it looked.

`PIPE_REQUIRE_PYTHON=1` makes tests fail if Python 3.10+ is not discovered. Cloud agents should export it before `cargo test`. Cursor `environment.json` installs the Ubuntu `python3` package.

## Fidelity vs IBM

For features we implement, match **IBM CMS Pipelines** (Author’s Edition / z/VM reference) — names, record semantics, dispatcher rules. Do not invent alternate spellings (e.g. no `WRITETO`; the write subcommand is `OUTPUT`). Out-of-scope items stay omitted rather than approximated under a different name; track them in [`builtins-roadmap.md`](builtins-roadmap.md).

## Ambiguities vs IBM

When behavior is unclear, we document the choice here and lock it with a test under `tests/compat/`.

| Topic | Choice |
|---|---|
| REXX write subcommand | IBM `OUTPUT` only (not `WRITETO`) |
| CALLPIPE connectors | IBM `*:` (buffering mode in v1; bare `*` synonym) |
| Stage error context | Author's Edition 1.1.11 messages chapter (CMS default MSGLEVEL 7 / bits 1+2+4; the book also lists default 15, which does not change messages 1–4). After a stage-attributed error we emit message 3 `... Issued from stage %d of pipeline %d` (message 4 with `NAME` instead of 3), then message 1 `... Running "…"`. Message 2 `... Processing "callpipe …"` is issued only for CALLPIPE/ADDPIPE, inserted after the primary line. No FPL numbers (existing `PIPE:` / `PIPES0001E` style). Numbers are 1-based per pipeline in the set; label-only references count as slots but errors come from the labeled **definition**. CALLPIPE nested sets restart at pipeline 1. Stages spawned by IF/NOT/CASEI have no origin (would invent a pipeline number). MSGLEVEL filtering on PIPE is not implemented; these lines always match default MSGLEVEL. |
| ANYCASE minimum | The book's syntax diagram writes `ANYcase` (min 3). Shared `is_anycase` matches that (`any` accepted, `an` rejected). Stages whose diagram is `ANYCase` and/or that also have `ANYof` (STRIP, SPLIT, CHOP, JOINCONT, LOCATE) use `is_anycase_min4` so `ANY` is ANYOF. |
| Regina ADDRESS name | `PIPELINE` (portable); on CMS the stage environment is unnamed |
| Regina stage I/O | Buffered (drain input → RexxStart → flush output) so Regina is never interleaved across coroutines. Regina’s interpreter is process-global and not safe for concurrent `RexxStart` on different threads; `run_with_regina` uses a process-wide owner-thread + depth lock (same-thread reentrant, other threads wait). The ADDRESS `PIPELINE` host pointer is process-wide (not thread-local) so a subcom on another thread still sees the host; `run_with_regina` saves/restores the previous slot (stack discipline). The subcom copies the host pointer out and drops the `HOST` guard before dispatch so CALLPIPE/ADDPIPE of another `.rexx` cannot deadlock on `HOST`. **Nested `RexxStart`:** Regina 3.9.x hangs if `RexxStart` is re-entered from an ADDRESS `PIPELINE` handler, so `run_with_regina` returns a clear stage error when this thread already owns a run; the inner `.rexx` runs through the subset interpreter with the nested dispatcher’s live `StageCtx`. Buffered CALLPIPE feeds remaining `buf_in` on leading `*:` and appends to `buf_out` on trailing `*:`. **Linux Regina 3.9.5 (Ubuntu `libregina3`):** a later `RexxStart` hangs once a previous `#[test]` that called it has returned. Same-function repeats and a single pipefix test function are fine. `pipe-rexx` keeps the RexxStart cases in one test; this is a Regina process-lifetime limitation, not a weakened expectation. |
| REXX stage arguments | IBM argument string via `PARSE ARG` (also exposed as `ARG.n` in the subset) |
| REXX subcommand quoting | Prefer IBM `'READTO VAR'` / `'OUTPUT' expr` so Regina does not substitute variables into the command |
| Regina OUTPUT remainder | p.648: the record is the command string after `OUTPUT` and exactly one blank, including leading and trailing blanks. The ADDRESS `PIPELINE` handler must not `trim()` the command or the remainder (same remainder rule as PIPCMD). The subset interpreter evaluates `'OUTPUT' expr` and writes that value, so it never treats the payload as a command string. Regina’s `IfcSubCmd` copies `CmdLen` bytes into the RXSTRING with no strip; Windows packaging ships Regina, which is why a trim here failed only on Windows. |
| REXX / Python `EXIT n` | Author's Edition 1.1.11 Chapter 6 and return codes p.219: the REXX program return code is the stage return code; PIPE then aggregates stage codes (most negative, else largest). Previously the subset interpreter stored `EXIT n` only in `host.rc` (the same slot as last-command `RC`, so a filter that ended after `READTO` EOF would look like 12) and Regina ignored `RexxStart` `retcode`. Both now call `StageCtx::set_return_code` for the program exit value only. Python `pipelines.exit(n)` does the same. |
| Operand scanning | The pipeline scanner only finds verbs, `\|`, labels, and ENDCHAR. A `\|` inside `/foo\|bar/` is still a stage separator (1.1.11 p.208): the book does **not** protect delimited strings at scan time. Two adjacent separators (`\|\|`) or end characters are self-escaping (pp.114–115). `ESCAPE` (no default) deletes the escape and forces the next character to be ordinary. `SEPARATOR` / `STAGESEP` and `ENDCHAR` take an xorc; `()`, `*`, `:`, `.`, and blank are reserved. Each stage then rescans `ParsedStage.raw_args` (`pipe_parser::scan_operands` / `operands_for_stage`). IBM filters treat `/ /` and `/foo bar/` as delimited strings and keep every blank. `COMMAND` word-splits so `/s` `/b` stay flags. `DISK`, `<`, `>`, and `>>` take the remainder as one host path, so `/tmp/x.txt` is not a delimited `/tmp/`. `LITERAL`, `FIND`, `NFIND`, `NOTFIND`, `FRLABEL`, `FROMLABEL`, `TOLABEL`, and `WHILELABEL` keep the text after exactly one blank (pp.412, 349, 438, 353, 559, 596), including a blank that sits before `\|`. STR forms (`STRFIND`, `STRNFIND`, `STRFRLABEL`, `STRTOLABEL`, `STRWHILELABEL`) use filter dstring scanning. |
| delimitedString | 1.1.11 p.194 (syntactic variables). A dstring is a pair of delimiters (`/abc/`; `,,` is the null string), a hexadecimal literal (`X`/`H` plus an even number of hex digits, e.g. `xf1f2f3`), or a binary literal (`B` plus 0/1 bits in a multiple of eight, e.g. `b11000001`). Operand rescan keeps `"…"` / `'…'` as pair dstrings (so PICK `"0800"` is not column 800). Shared `decode_dstring` is used everywhere a stage accepts a dstring. Hex/binary decode to raw bytes; the book’s `xf1f2f3` → `123` example is EBCDIC, so portable ASCII uses `x313233` for those characters. The `STRING` place-holder form (`str xabx`) is out of scope. |
| `*` connector vs operand vs Windows globs | A lone `*` that is an entire stage is a CALLPIPE connector (a connector stage, `*:`, `*.input:`, or `*.output:`). A lone `*` after a stage verb is the operand star (`take *`, `drop last *`). Path/glob stars (`c:\*.*`, `*.json`) stay Words. |
| TAKE / DROP remainder | Record counts with `FIRST` (default), `LAST`, a number (default 1), `0`, and `*`. `BYTES` is rejected. The counted records and the others go to opposite streams (TAKE keeps the count on primary; DROP is the converse). After the count, the counted stream is severed once its in-flight record is consumed, then the remainder is copied. Our `short` severs; it does not splice the producer onto the other stream. If the remainder stream is not connected, the input is severed instead of draining the file. |
| NLOCATE null string | Same contains-subset as LOCATE, routes inverted. No operand (or an empty delimited string) selects only empty records. `NOTLOCATE` is the documented synonym. |
| STRIP targets | 1.1.11 pp.532–533. Character or string trim. Default is both ends, blank. `LEADING` / `TRAILING` / `BOTH`, `BLANK`, a one-character word, a delimited set, `ANYOF` (min 3), `STRING` (min 3), xrange (`xorc-xorc` / `xorc.n`), `NOT` / `TO`, `ANYCASE` (min 4; `ANYOF` wins at 3), and an optional per-side count are implemented. |
| SPLIT | Full stage per Author's Edition 1.1.11 pp. 505–506. Operand order is fixed: `[ANYCase] [MINimum number] [AT \| [snumber] BEFORE \| [snumber] AFTER] [NOT] [BLANK \| target [number]]`. Target is an `xrange` (xorc, `xorc-xorc`, `xorc.number`), `STRing dstring`, or `ANYof dstring`; a one-character dstring may omit the keyword. Default target is blank. `AT` (default) discards the match; `BEFORE`/`AFTER` keep it, with signed offsets (`n AFTER` ≡ `m BEFORE` where `m = -n - length(target)`). Note 1: null input records are copied; generated null records are dropped. Abbreviations: `ANYCase` min 4 (`ANYof` wins at 3), `MINimum` min 3, `STRing` min 3; `CASEANY` / `IGNORECASE` / `CASEIGNORE` synonym `ANYCASE`. Portable ASCII: `BLANK`/`SPACE` xorc is X'20' (book cites EBCDIC X'40'); `TABULATE` xorc is ASCII HT X'09' (book cites EBCDIC X'05'). |
| BETWEEN / INSIDE / NOTINSIDE / OUTSIDE | Full family, one implementation. Author's Edition 1.1.11 pp.272–273 (BETWEEN), p.393 (INSIDE), pp.442–443 (NOTINSIDE), pp.445–446 (OUTSIDE). Type: Selection stage. Shared syntax: `[ANYcase] dstring (number \| dstring)` after the verb. `ANYcase` min 3; Notes synonyms `CASEANY` / `IGNORECASE` / `CASEIGNORE` (pp.273, 394, 443, 446). Match is a prefix compare (“begins with”), not substring contains. Verbs: `BETWEEN` / `INSIDE` / `OUTSIDE` all-caps (no prefix); `NOTINSIDe` min 7 (p.442); synonym `NINSIDE` (p.443 Note 1). BETWEEN/OUTSIDE **include** the start and end label records; the count must be 2 or larger. INSIDE/NOTINSIDE **exclude** the labels (the group begins after the start match and ends before the end match); the count must be non-negative (0 is an empty group). The start record is never also the end of the same group (“the next record”). After an exclusive group closes, the end label is not reused as the next start. Selected groups go to primary for BETWEEN/INSIDE and to secondary for the converses (OUTSIDE / NOTINSIDE). Records before, between, and after groups go to the other stream (discarded if that stream is not connected). Open groups run to EOF. Repeated groups are selected (unlike FRLABEL+TOLABEL). Streams: primary input; secondary input must not be connected; tertiary and higher inputs rejected so a producer is not parked. Premature termination when no output stream is connected. Record delay: strictly does not delay — `peek`, write, then consume. Commit −2 then 0: the engine auto-commits stages to 0. No dispatcher changes. Column ranges, bit masks, bare words, `RANGE`, `FIRST`, signed/star counts, and ANYCASE after the first dstring are not in the syntax diagram and are rejected. **Ambiguity — earlier subset note:** the previous BETWEEN row listed “column ranges/masks rejected” as a subset gap. The 1.1.11 diagrams document no column range for this family; that was never a missing operand. **Ambiguity — number token:** `number` (not `snumber`); unsigned decimal digits only. **Ambiguity — end label as next start:** the book consumes the end record as the end of the group. **Ambiguity — extra inputs:** the inventory forbids a connected secondary input; we also reject streams above secondary. The OUTSIDE heading example (`mctoasa \| outside /1/ 2`, p.446) uses an ASCII `1` prefix here (`mctoasa` is out of scope). |
| LITERAL argument | 1.1.11 pp.412–413. The string starts after exactly one blank; extra blanks are kept. Omitted argument writes a null record, then input is copied (so `literal a\|literal b` yields `b` then `a`). A space before `\|` is a trailing blank in the argument. |
| CHANGE occurrences | 1.1.11 pp.286–288. Default is every occurrence (not first-only). A null first string prefixes once. `ANYCASE` uses the book’s case-of-match rule when the old string is lowercase. Invented `FIRST` is rejected. Column ranges stay subset. |
| COUNT keywords | 1.1.11 p.306 requires at least one keyword (`CHARACTERs` / `WORDS` / `LINES` / `MINline` / `MAXline`). Bare `COUNT` is rejected. `CHARACTERs` minimum abbreviation is 8; `CHARS` / `BYTES` are documented synonyms for characters; `RECORDS` is a synonym for `LINES`. Empty input: min length is 2G−1, max is 0. When the secondary output is connected, input records are copied to the primary and the count is written to the secondary at end-of-file. The primary is closed as EOF (not SHORT) so a later BUFFER or SORT still emits the copies. |
| CONSOLE placement | 1.1.11 pp.303–305. First vs not-first is “primary input connected?”, matching device-driver placement. `TERMINAL` is a synonym. CMS-only `DIRECT` / `DARK` / `INVISIBLE` / `ASYNCHRONOUSLY` are rejected. |
| DISK vs diskfast | 1.1.11 p.328. First stage reads; missing file is a null file. Not-first appends/creates and copies through. Invented `OUTPUT` / `APPEND` operands are rejected (`use > or >>`). |
| File stages `<` `>` `>>` | 1.1.11 pp.230, 237, 245. `<` must be first and reads; a missing file is an error (not diskfast-empty). `>` must not be first; it replaces or creates. `>>` must not be first; it appends or creates. Both writers copy records to the primary output (they do not delay the record). Operand is one portable host path, not CMS `fn ft fm`. A blank is required after the verb (`< file.txt`, not `<file.txt`). |
| Host-file / device records | Portable device drivers (`<`, `>`, `>>`, DISK, COMMAND stdout, CONSOLE/TERMINAL) treat the host stream as bytes, not UTF-8 text. `pipe_core::Record` is already a byte string. Readers split on LF (X'0A') and strip a single CR (X'0D') immediately before that LF — the same convention `BufRead::lines` used, without the UTF-8 requirement. Writers emit the record bytes followed by LF. No encoding conversion and no invented operands: a UTF-16 file (for example a SQL Server `.sqlplan` with a UTF-16LE BOM) is passed through as raw bytes, the same way CMS would treat a binary file. `< x \| > y` is byte-identical except for that CR-before-LF normalization and a trailing LF after each written record. |

| FANINTWO | Full stage per Author's Edition 1.1.11 pp.340–341. Type: Arcane gateway. Syntax (diagram all-caps): `FANINTWO`. No operands; extras and invented keywords (`STRICT`, `STOP`, numbers, …) are rejected. No verb prefix (`fanintw` is unknown). Streams: primary and optional secondary input; primary output only (any other output is rejected at commit). Tertiary and higher inputs are rejected. Operation: pass whichever input has a record to the primary output, giving priority to the secondary. When a primary record is waiting, FANINTWO yields (`yield_others`) so a secondary producer can catch up, then drains secondary records (peek, write, consume — strictly no delay) before writing the primary. After writing a primary-originated record, it again drains secondary arrivals before consuming the primary, so the primary record is delayed by those secondary records. Premature termination when the primary output is not connected. Commit −2 then 0: the engine auto-commits stages to 0. End-of-file on the output: stop; remaining input is `short_input` so a producer is not parked (our SHORT severs; it does not splice). **Ambiguity — “suspends itself”:** p.340; `StageCtx::yield_others`. **Ambiguity — one input only:** secondary may be omitted; primary records copy through. |
| FANOUTWO | Full stage per Author's Edition 1.1.11 pp.342–343 (tutorial p.90 Figure 180). Type: Gateway. Syntax (diagram all-caps): `FANOUTWO`. No operands; extras rejected. No verb prefix (`fanoutw` is unknown). Streams: primary input only; two streams must be defined (secondary output required); tertiary and higher rejected. Operation: write each record to the primary output, then to the secondary. End-of-file on the primary output stops the stage without consuming that record and without writing it to the secondary (EOF travels backwards). End-of-file on the secondary: consume the current record (already on primary) and copy remaining input to the primary only — IBM SHORT splice stand-in (`copy` + `short_input` if primary later severs). Record delay: strictly does not delay (write both, then consume). Commit −2 then 0: verify secondary input is not connected (covered by the extra-input check). | FILLUP | Full stage per Author's Edition 1.1.11 p.345. Type: Gateway. Syntax (diagram all-caps): `FILLUP`. No operands; extras rejected. No verb prefix (`fillu` is unknown). Streams: primary input only (any other input is rejected). Operation: write to the primary output first. When that consumer severs (EOF backwards), switch to the next connected output (secondary, tertiary, …) and retry the record that could not be written. When only one output remains, remaining input is copied there (IBM SHORT splice stand-in). When no output remains, `short_input` and stop. ## TRACE

`(TRACE)` in the options group, or CLI `--trace` / `-t`, enables `TraceConfig` on the dispatcher. Events: dispatcher start/end, stage start/end, READ/WRITE (length + short preview), COMMIT request/wait/proceed, SHORT, DELAY, STOP external waits, CALLPIPE enter/exit. Output defaults to stderr with a `PIPE TRACE:` prefix; tests may use `TraceConfig::capture`.
