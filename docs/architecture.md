# Architecture: CMS Pipelines → Rust

## Design rules (Hartmann)

1. **Stages never call each other.** They call dispatcher services on `StageCtx`: `read`, `write`, `commit`, `delay_record`, `short`, `callpipe`.
2. **Records**, not byte streams, are the unit of transfer (`pipe_core::Record`).
3. **At most one record in flight** per connection unless a stage explicitly buffers (`BUFFER`, `SORT`).
4. **Drain-biased scheduling:** consumers that can read are preferred over producers.
5. **Device drivers vs filters:** disk/command/console live in driver stages; filters only transform records.

## Type map

| CMS concept | Rust |
|---|---|
| Record | `pipe_core::Record` |
| Stream number | `pipe_core::StreamId` |
| Stage | coroutine running a `StageFn` / `FnOnce(&mut StageCtx)` |
| Dispatcher | `pipe_core::Dispatcher` via `PipelineBuilder::run` |
| PIPE specification | `pipe_parser::parse_pipeline` |
| Built-in program | factory in `pipe_stages::StageRegistry` |
| CALLPIPE | `StageCtx::callpipe` + connectors |
| REXX stage | `pipe_rexx` (`READTO` / `OUTPUT` / `CALLPIPE` / …) |

## Coroutine model

Each stage runs on a **stackful coroutine** (`corosensei`). When `read`/`write`/`commit` cannot complete, the stage **suspends**; the dispatcher resumes another ready stage. A thread-local holds the current `Yielder` so `StageCtx` stays easy to call.

## Multi-stream labels

```text
(ENDCHAR ?) literal a|literal b | L: locate /a/ | console ? L: | console
```

- First `L:` defines the stage and its primary streams.
- Later `L:` occurrences attach secondary/tertiary streams of that same stage instance.

## CALLPIPE / ADDPIPE

Nested specifications may start/end with IBM `*:` connectors (bare `*` still
accepted as a synonym):

- Leading `*:` — feed nested pipeline from the caller’s selected input.
- Trailing `*:` — drain nested output to the caller’s selected output.
- Also recognized: `*.input:`, `*.output:`.

v1 implements connector CALLPIPE in **buffering** mode (read all → run nested → write all), which is record-correct and sufficient for REXX filters. Streaming bridges can replace this later without changing the stage API.

## REXX / Regina

`pipe-rexx` runs `.rexx` stages with this preference order:

1. **Regina** (user-installed) — dynamically load `regina.dll` / `libregina.so` / `libregina.dylib`, register ADDRESS `PIPELINE`, `RexxStart` the script file.
2. **Subset interpreter** — if Regina is not found or cannot load.

Discovery env vars: `PIPE_REGINA`, `REGINA`, `REGINA_HOME` (file or directory). Also searches PATH, the `pipe` executable directory, and common install prefixes.

Pipeline subcommands use **IBM names only** (ADDRESS `PIPELINE` / subset statements):

| Subcommand | Meaning |
|---|---|
| `READTO var` | Read one record; RC=12 at EOF |
| `OUTPUT` | Write a record (command string after verb) |
| `CALLPIPE` | Nested pipeline |
| `ADDPIPE` | Attach nested network (v1 ≈ CALLPIPE) |
| `SHORT` | Sever selected streams |
| `SELECT INPUT/OUTPUT n` | Choose stream |
| `COMMIT n` | Commit level (Regina path) |
| `PEEKTO` | Not yet |

## Fidelity vs IBM

For features we implement, match **IBM CMS Pipelines** (Author’s Edition / z/VM reference) — names, record semantics, dispatcher rules. Do not invent alternate spellings (e.g. no `WRITETO`; the write subcommand is `OUTPUT`). Out-of-scope items stay omitted rather than approximated under a different name; track them in [`builtins-roadmap.md`](builtins-roadmap.md).

When behavior is unclear, we document the choice here and lock it with a test under `tests/compat/`.

| Topic | Choice |

| Regina ADDRESS name | `PIPELINE` (portable); on CMS the stage environment is unnamed |
| Regina stage I/O | Buffered (drain input → RexxStart → flush output) so Regina is never interleaved across coroutines |

| Operand scanning | The pipeline scanner only finds verbs, `\|`, labels, and ENDCHAR. A `\|` inside `/foo\|bar/` is still a stage separator (1.1.11 p.208): the book does **not** protect delimited strings at scan time. Two adjacent separators (`\|\|`) or end characters are self-escaping (pp.114–115). `ESCAPE` (no default) deletes the escape and forces the next character to be ordinary. `SEPARATOR` / `STAGESEP` and `ENDCHAR` take an xorc; `()`, `*`, `:`, `.`, and blank are reserved. Each stage then rescans `ParsedStage.raw_args` (`pipe_parser::scan_operands` / `operands_for_stage`). IBM filters treat `/ /` and `/foo bar/` as delimited strings and keep every blank. `COMMAND` word-splits so `/s` `/b` stay flags. `DISK`, `<`, `>`, and `>>` take the remainder as one host path, so `/tmp/x.txt` is not a delimited `/tmp/`. `LITERAL` keeps the text after exactly one blank (p.412), including a blank that sits before `\|`. |
| delimitedString | 1.1.11 p.194 (syntactic variables). A dstring is a pair of delimiters (`/abc/`; `,,` is the null string), a hexadecimal literal (`X`/`H` plus an even number of hex digits, e.g. `xf1f2f3`), or a binary literal (`B` plus 0/1 bits in a multiple of eight, e.g. `b11000001`). Operand rescan keeps `"…"` / `'…'` as pair dstrings (so PICK `"0800"` is not column 800). Shared `decode_dstring` is used everywhere a stage accepts a dstring. Hex/binary decode to raw bytes; the book’s `xf1f2f3` → `123` example is EBCDIC, so portable ASCII uses `x313233` for those characters. The `STRING` place-holder form (`str xabx`) is out of scope. |
| `*` connector vs operand vs Windows globs | A lone `*` that is an entire stage is a CALLPIPE connector (a connector stage, `*:`, `*.input:`, or `*.output:`). A lone `*` after a stage verb is the operand star (`take *`, `drop last *`). Path/glob stars (`c:\*.*`, `*.json`) stay Words. |
| TAKE / DROP remainder | Record counts with `FIRST` (default), `LAST`, a number (default 1), `0`, and `*`. `BYTES` is rejected. The counted records and the others go to opposite streams (TAKE keeps the count on primary; DROP is the converse). After the count, the counted stream is severed once its in-flight record is consumed, then the remainder is copied. Our `short` severs; it does not splice the producer onto the other stream. If the remainder stream is not connected, the input is severed instead of draining the file. |
| NLOCATE null string | Same contains-subset as LOCATE, routes inverted. No operand (or an empty delimited string) selects only empty records. `NOTLOCATE` is the documented synonym. |
| STRIP targets | 1.1.11 pp.532–533. Character or string trim. Default is both ends, blank. `LEADING` / `TRAILING` / `BOTH`, `BLANK`, a one-character word, a delimited set, `ANYOF` (min 3), `STRING` (min 3), xrange (`xorc-xorc` / `xorc.n`), `NOT` / `TO`, `ANYCASE` (min 4; `ANYOF` wins at 3), and an optional per-side count are implemented. |
| SPLIT | Full stage per Author's Edition 1.1.11 pp. 505–506. Operand order is fixed: `[ANYCase] [MINimum number] [AT \| [snumber] BEFORE \| [snumber] AFTER] [NOT] [BLANK \| target [number]]`. Target is an `xrange` (xorc, `xorc-xorc`, `xorc.number`), `STRing dstring`, or `ANYof dstring`; a one-character dstring may omit the keyword. Default target is blank. `AT` (default) discards the match; `BEFORE`/`AFTER` keep it, with signed offsets (`n AFTER` ≡ `m BEFORE` where `m = -n - length(target)`). Note 1: null input records are copied; generated null records are dropped. Abbreviations: `ANYCase` min 4 (`ANYof` wins at 3), `MINimum` min 3, `STRing` min 3; `CASEANY` / `IGNORECASE` / `CASEIGNORE` synonym `ANYCASE`. Portable ASCII: `BLANK`/`SPACE` xorc is X'20' (book cites EBCDIC X'40'); `TABULATE` xorc is ASCII HT X'09' (book cites EBCDIC X'05'). |
| BETWEEN operands | 1.1.11 pp.272–273. Requires two operands (plus optional ANYCASE / CASEANY / IGNORECASE / CASEIGNORE before them). A group begins with a record that **begins with** the first string (prefix, not substring contains). The group ends at the next prefix match of the second string, or after a count of records (the count must be 2 or larger). Selected records go to primary output; others to secondary. Column ranges and bit masks are rejected. OUTSIDE/INSIDE/NOTINSIDE remain in phase 6. |
| LITERAL argument | 1.1.11 pp.412–413. The string starts after exactly one blank; extra blanks are kept. Omitted argument writes a null record, then input is copied (so `literal a\|literal b` yields `b` then `a`). A space before `\|` is a trailing blank in the argument. |
| CHANGE occurrences | 1.1.11 pp.286–288. Default is every occurrence (not first-only). A null first string prefixes once. `ANYCASE` uses the book’s case-of-match rule when the old string is lowercase. Invented `FIRST` is rejected. Column ranges stay subset. |
| COUNT keywords | 1.1.11 p.306 requires at least one keyword (`CHARACTERs` / `WORDS` / `LINES` / `MINline` / `MAXline`). Bare `COUNT` is rejected. `CHARACTERs` minimum abbreviation is 8; `CHARS` / `BYTES` are documented synonyms for characters; `RECORDS` is a synonym for `LINES`. Empty input: min length is 2G−1, max is 0. |
| CONSOLE placement | 1.1.11 pp.303–305. First vs not-first is “primary input connected?”, matching device-driver placement. `TERMINAL` is a synonym. CMS-only `DIRECT` / `DARK` / `INVISIBLE` / `ASYNCHRONOUSLY` are rejected. |
| DISK vs diskfast | 1.1.11 p.328. First stage reads; missing file is a null file. Not-first appends/creates and copies through. Invented `OUTPUT` / `APPEND` operands are rejected (`use > or >>`). |
| File stages `<` `>` `>>` | 1.1.11 pp.230, 237, 245. `<` must be first and reads; a missing file is an error (not diskfast-empty). `>` must not be first; it replaces or creates. `>>` must not be first; it appends or creates. Both writers copy records to the primary output (they do not delay the record). Operand is one portable host path, not CMS `fn ft fm`. A blank is required after the verb (`< file.txt`, not `<file.txt`). |
| Host-file / device records | Portable device drivers (`<`, `>`, `>>`, DISK, COMMAND stdout, CONSOLE/TERMINAL) treat the host stream as bytes, not UTF-8 text. `pipe_core::Record` is already a byte string. Readers split on LF (X'0A') and strip a single CR (X'0D') immediately before that LF — the same convention `BufRead::lines` used, without the UTF-8 requirement. Writers emit the record bytes followed by LF. No encoding conversion and no invented operands: a UTF-16 file (for example a SQL Server `.sqlplan` with a UTF-16LE BOM) is passed through as raw bytes, the same way CMS would treat a binary file. `< x \| > y` is byte-identical except for that CR-before-LF normalization and a trailing LF after each written record. |
| FANIN / FANOUT / FANINANY | FANIN (p.338) reads connected inputs in order, or a numeric stream list. Named stream identifiers are rejected. FANINANY (p.339) uses `read_any`; `STRICT` is accepted. FANOUT (p.341) writes every connected output; `STOP ALLEOF` / `ANYEOF` / `n`. |
| COPY / HOLE operands | COPY (p.305) and HOLE (p.382) take no operands; extras are rejected. COPY consumes each record before writing (one-record delay potential). HOLE drains every connected input. |
| JOIN | Full stage per Author's Edition 1.1.11 pp. 399–401. Operand order is fixed: `[COUNT] [number \| * \| KEYLENgth number] [delimitedString [TERMinate]] [number]`. The first number is how many records are appended to the first of a set (default 1 = pairs; 0 = one-record sets; `*` = all). When a secondary input is connected and no number/`*`/`KEYLENGTH` is given, the default is unlimited. The second number is a maximum output length in bytes, exclusive of the COUNT prefix; it cannot be the first word. An input record at least that long is written unchanged (not truncated). `COUNT` prefixes a 10-character right-aligned contributor count. `KEYLENgth` (min 6) joins while the leading key matches and drops the key from records 2–n; a record shorter than the key uses the whole record as the key. `TERMinate` (min 4) appends the insert string after the last record of a set. Null input records are ordinary empty contributors, not set terminators; a set that contains only nulls writes a null record; no input writes nothing. Records go to the primary output only; a connected secondary output is rejected. Secondary input flushes the buffer and discards that record (EOF on primary is ignored while secondary is live). When both inputs have a record, primary is consumed first so a split-then-join rebuild can drain pieces before a fanout copy flushes. `TERMINATE` is applied at flush and is not included in the “would this input record exceed the maximum?” check. No documented synonyms; `ANYCASE` is rejected. JOIN 0 does not splice streams (our `short` severs). The book's blank insert `/ /` is a delimited string (see Operand scanning). |
| CHOP | Full stage per Author's Edition 1.1.11 pp. 289–290 (tutorial pp.6, 12, 57–59). Two forms, fixed order: (1) `CHOP` / `TRUNCate` `[number]` truncates after that 1-based column (default 80; `chop 0` is a null record; records are not padded). A **lone decimal number is a column**, not xorc — unlike SPLIT, where `11` is X'11'. (2) `CHOP [ANYCase] [[snumber] BEFORE \| AFTER] [NOT] target` with target `xrange` / `STRing dstring` / `ANYof dstring` (one-character dstring may omit the keyword). Default placement is BEFORE the first match; AFTER keeps the match on the primary. `n AFTER` ≡ `m BEFORE` with `m = -n - length(target)` (p.59). NOT with a character is the complement set; NOT with a string skips occurrences and the match length is 1 (p.59). No match: whole record to primary, null remainder to secondary. Data before the chop position → primary; the remainder → secondary if connected (null remainders are written). Secondary input is rejected. Premature termination when **no** output stream is connected. `ANYCASE` min 4 (`ANYOF` wins at 3); synonyms `CASEANY` / `IGNORECASE` / `CASEIGNORE`. `STRING` min 3, `ANYOF` min 3; `BEFORE` / `AFTER` / `NOT` are whole words. `AT` and `MINIMUM` are SPLIT-only and rejected. `TRUNCATE` is the documented synonym (`TRUNCate`, min 5). `chop before 80` is BEFORE + xorc X'80', not column 80. Portable ASCII: `BLANK`/`SPACE` X'20' (book X'40'); `TABULATE` HT X'09' (book X'05'). `examples/chop.rexx` is a REXX `SUBSTR` sample, **not** this built-in. |

Operand order is fixed: `[ANYCase] [NOT] [TRAILING \| RANGE inputRange \| LEADING] [DELAY] [ANYof] delimitedString [KEEP] [delimitedString]`. Default location is TRAILING. Continuation string is required. The second dstring is inserted only *between* joined records (not after EOF). A record that does **not** indicate continuation ends the current set and is included in it; a record that is not part of a set is written unmodified. The continuation string/character is deleted unless `NOT` or `KEEP` is specified; `RANGE` implies KEEP. `ANYOF` (min 3) treats the dstring as a character set and compares one character (last of the record, first of the next, or the single-byte contents of the range). `ANYCASE` min 4 because ANYOF wins at 3; synonyms `CASEANY` / `IGNORECASE` / `CASEIGNORE` (not NetRexx `CASELESS`). `TRAILING` / `LEADING` / `RANGE` / `DELAY` / `KEEP` / `NOT` are whole words. Null records: a null does not carry a non-empty marker; a marker-only record at EOF writes a null after the strip. Streams: primary in / primary out. | xrange helper | Shared `pipe_stages` module `xrange` (xorc / xrange / STRING / ANYOF, 1.1.11 pp.194–197). SPLIT and CHOP share `ByteSet`, `find_match`, and `n AFTER` ≡ `m BEFORE` cut indices. `input_range` xorc parsing uses the same `parse_xorc`. |

| DUPLICATE | Full stage per Author's Edition 1.1.11 p.334 (tutorial Figure 245 p.148; delay examples p.322). Syntax: `DUPlicate [snumber \| *]`. | ZONE | Subset per Author's Edition 1.1.11 pp. 610–611 (tutorial p.52; Figure 140 p.67). Operand order is fixed: `ZONE inputRange [CASEI] [REVERSE] word [string]`. Missing input fields without an explicit output length are ignored (no pad to that column, p.159); a null literal is stored (p.499); a cycle that places nothing still writes a null record (p.156). Portable conversions: `C2X`/`X2C`/`C2B`/`B2C` and composites `X2B`/`B2X`. C2B/B2C use ASCII `0`/`1` (book cites EBCDIC X'F0'/X'F1', p.625). Hex literals such as the book's `x5c` asterisk are EBCDIC; portable ASCII uses `x2a`. `NUMBER` is a 10-byte right-aligned field with leading blanks (p.498); each `NUMBER` item has its own counter, incremented at end of cycle, not on `WRITE`. Streams: primary in / primary out. A connected secondary output is rejected (inventory commit check p.500); `OUTSTREAM` is later. Secondary input is ignored until `SELECT`. Premature termination when the primary output is not connected. **Ambiguity — tutorial figures vs columns:** several Ch.14 figures print collapsed blanks (`First*` / `Odd reco *****`). We write the pad characters the column rules require (Figures 259, 270, 273–277). **Ambiguity — empty specification:** p.497 requires one or more items. The previous subset copied the record; empty `SPEC` is now rejected. **Ambiguity — trailing `WRITE`:** the book does not say whether the end-of-cycle write still emits the emptied buffer. We skip that final write when `WRITE` left the buffer empty. **Ambiguity — `N` vs `NUMBER`:** `Next` is min 1; `NUMBER` is a whole word, so `N` is `NEXT`. Expression language, `TODCLOCK`, remaining conversions, `STOP`/`PRINTONLY`/`SELECT`/`ID` stay unimplemented and are rejected by name. |
| UNIQUE | Full stage per Author's Edition 1.1.11 pp. 572–574 (tutorial Figure 116 p.56). Operand order: `[COUNT] [NOPAD \| PAD xorc] [ANYcase] [uniqueRanges] [LAST \| SINGLEs \| FIRST \| MULTiple \| PAIRwise]`. Default is NOPAD + LAST + the whole record as the key. Compatibility (p.572): COUNT and the selection keyword may appear before a trailing range, or both after the range. `PAIRWISE` cannot combine with `COUNT`. Selection: FIRST = first of each adjacent run; LAST = last of each run; SINGLES = singleton runs only; MULTIPLE = runs of two or more (the complete set); PAIRWISE = non-overlapping pairs, both records to primary when keys differ. Records not selected go to the secondary output (discarded if it is not connected). `COUNT` prefixes every written record with a 10-character right-aligned position in the run (starting at 1); with LAST that position on the primary record is the run length. `PAD xorc` extends the shorter of two extracted keys before compare; NOPAD requires equal extracted lengths. `ANYCASE` min 3 (UNIQUE has no `ANYOF`); synonyms `CASEANY` / `IGNORECASE` / `CASEIGNORE` (Note 4). `SINGLEs` min 6, `MULTiple` min 4, `PAIRwise` min 4; `COUNT` / `PAD` / `NOPAD` / `FIRST` / `LAST` are whole words. uniqueRanges is one `inputRange` or `( inputRange [NOPAD \| PAD xorc] … )`; a parenthesized field may override the global pad. Secondary input is rejected. Premature termination when **no** output stream is connected. Record delay: FIRST writes immediately; LAST / SINGLES / MULTIPLE delay one record; PAIRWISE delays the first of a pair. **Ambiguity — PAIRWISE leftover:** the book does not say what happens to an odd last record. We write it to the primary (it has no partner, so it is not a duplicate pair). **Ambiguity — COUNT on secondary:** “each record is prefixed” (p.573), so secondary records also get the position prefix. Adjacent-only compare (Note 1); `NOT UNIQUE` stays the Phase 6 `NOT` prefix. Portable ASCII xorc: `BLANK`/`SPACE` X'20' (book cites EBCDIC X'40'). |
| PREFACE | Full stage per Author's Edition 1.1.11 pp.461–462. Syntax: `PREFACE string` (diagram all-caps). The argument is a subroutine pipeline issued with CALLPIPE: separator `\|`, escape `"`, end-character `\`; beginning unconnected; end drained to PREFACE’s primary output (do not write `*:`). Nested records are written first; then primary input is copied to primary output. Record delay: the input file is delayed by the number of nested records. Premature termination when the primary output is not connected or CALLPIPE fails. Secondary input is rejected. A connected secondary output is unused. The nested spec is reconstructed by joining PREFACE’s operand tokens with blanks (`literal a b \|\| split` → `literal a b \| split`). **Ambiguity — commit −1:** p.461; the engine auto-commits stages to 0. **Ambiguity — nested references to PREFACE streams:** the book allows the nested spec to name every defined stream except PREFACE’s primary output. This increment does not wire those references. **Ambiguity — STEM/VAR in the nested spec:** out of scope until Phase 5. |
| APPEND | Full stage per Author's Edition 1.1.11 pp.263–264. Syntax: `APPEND string` (diagram all-caps). Same nested CALLPIPE rules as PREFACE. Copy primary input to primary output first, then run the nested specification. Record delay: APPEND strictly does not delay the input record; nested records wait until EOF. Premature termination if the primary output is not connected or the copy cannot finish before the nested CALLPIPE. Secondary input is rejected. A connected secondary output is unused. **Ambiguity — `callpipe *:\|*: ` copy:** p.263 says the input is shorted through a connector CALLPIPE so the copy does not delay. v1 connector CALLPIPE buffers until EOF, which *would* delay, so we copy with `read`/`write` instead and only CALLPIPE the argument string. Streaming connector CALLPIPE stays Phase 4. Commit −1, nested stream references, and STEM/VAR: same omissions as PREFACE. |

## Pipeline fixtures

End-to-end specifications live in `tests/pipelines/*.pipefix`: a PIPE string plus
the records (or error substring) it must produce. `CONSOLE` is rewritten to an
in-memory collector; the runner does not spawn the CLI. `examples/README.md`
`pipe "…"` lines are harvested into `readme-harvest.pipefix`; a completeness test
fails if a README example is missing. See `tests/pipelines/README.md`. This is
not a cartesian product of operands — book and README pipes, plus documented
rejects.

## TRACE

`(TRACE)` in the options group, or CLI `--trace` / `-t`, enables `TraceConfig` on the dispatcher. Events: dispatcher start/end, stage start/end, READ/WRITE (length + short preview), COMMIT request/wait/proceed, SHORT, DELAY, CALLPIPE enter/exit. Output defaults to stderr with a `PIPE TRACE:` prefix; tests may use `TraceConfig::capture`.
